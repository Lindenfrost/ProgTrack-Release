ProgTrack – Guida utente

ProgTrack è un'applicazione interattiva per tracciare livelli ormonali, pesi, interventi chirurgici ed eventi riproduttivi negli animali da laboratorio. Visualizza serie temporali, applica limiti specifici per animale e, tramite plugin opzionali, offre strumenti di pianificazione e di reportistica.

1. Introduzione e concetti chiave

ProgTrack è costruito attorno ai singoli animali. Per ogni animale è possibile registrare misurazioni ormonali (progesterone ematico, PdG urinario), pesi, parametri dello sperma, interventi e eventi riproduttivi. I dati vengono visualizzati come grafici di serie temporali e riassunti in statistiche.

Concetti importanti:

  • Animale – una voce nell'elenco sulla sinistra. Ogni animale ha un nome univoco e un ruolo specifico.
  • Ruolo – determina come viene utilizzato l'animale (ad es. Donatrice di ovociti, Surrogata, Donatore di sperma, Prole, Partner, Animale da riproduzione) e quali limiti si applicano.
  • Misurazioni – dati con indicazione della data per progesterone, PdG, peso e qualità dello sperma.
  • Eventi – interventi chirurgici, trasferimenti di embrioni, gravidanze, parti, iniezioni di PGF/FSH e altri eventi riproduttivi.
  • Plugin – moduli opzionali per pianificazione avanzata, reportistica, tracciamento degli embrioni e comunicazione nel team.
Struttura attuale: ProgTrack è modulare. Il core gestisce database animali, grafici, importazioni, lingua/stile e schede principali. I plugin aggiungono schede, dialoghi, controlli permessi, report e archivi dati specifici. Alcuni moduli sono schede, altri finestre separate, e alcuni sono feature gate che abilitano controlli aggiuntivi.

2. Avvio di ProgTrack e file di dati

2.1 Avvio del programma

  • Aprire Launcher.exe nella cartella portatile di ProgTrack.
  • Il launcher avvia il primo file ProgTrack.v.*.py trovato accanto a sé, in ordine naturale. Uno script specifico può essere indicato con --script.
  • Plugins, icons, lang, manual e lo script payload attivo devono restare accanto a Launcher.exe.
  • Il launcher compilato contiene già il runtime Python necessario; gli utenti del pacchetto portatile non devono installare pacchetti Python.
Suggerimento: Se l'applicazione non parte, controllare launcher_error.log e launcher_fault.log in ProgTrackData/state/logs per un'installazione portatile scrivibile, oppure nella directory di stato utente dell'installazione.

2.2 Profili backend e dati gestiti

ProgTrack usa un unico livello di accesso ai dati con due profili:

ProfiloUso
Standalone SQLiteUna sola workstation locale o test; solo memoria locale non sincronizzata.
Shared PostgreSQLUso in rete e multi-workstation con backend condiviso.

Accedere come Lord e aprire Impostazioni → Backend per scegliere il profilo usato dopo il prossimo riavvio completo. Per Standalone SQLite scegliere un nome file .sqlite3 sicuro e una cartella locale assoluta. Shared PostgreSQL offre host, porta, database, utente, password, modalità SSL, timeout, archivio documenti gestito e dimensioni del pool. Usare Verifica connessione prima di salvare PostgreSQL. La password viene conservata nell'archivio credenziali del sistema operativo. Il salvataggio non trasferisce dati; usare il flusso completo di esportazione/importazione. Le variabili d'ambiente di distribuzione mantengono la priorità per l'amministrazione headless.

In una cartella portatile scrivibile, i dati modificabili risiedono sotto ProgTrackData: il database predefinito è database/progtrack.sqlite3, configurazione e preferenze sono sotto config, documenti caricati e asset del branding sotto managed, log e blocco Standalone sotto state, ed esportazioni predefinite sotto exports. Le installazioni di sola lettura usano invece il profilo utente Windows o le directory XDG di Linux.

Il backend configurato è l'unica fonte operativa. Se non è disponibile, l'avvio segnala l'errore e non passa all'altro profilo. La release include il driver client PostgreSQL, non il server; configurazione del server e verifiche di distribuzione PostgreSQL/Linux sono test di installazione separati.

Non usare Standalone SQLite su unità di rete o cartelle cloud sincronizzate. Usare il pacchetto interchange completo per backup e trasferimento.

Standalone SQLite ammette un solo processo ProgTrack in scrittura. Una seconda istanza viene rifiutata finché il proprietario attivo mantiene state/runtime/standalone.lock; i blocchi locali orfani vengono recuperati in sicurezza. Le scritture controllate in entrambi i profili usano revisioni ed entity lock. Solo un'operazione autorizzata come Lord può forzare il rilascio di un entity lock; il motivo è obbligatorio e registrato.

Solo un backend realmente vuoto viene inizializzato dall'unico pacchetto deterministico e interamente fittizio in Resources/Seed. Un database esistente resta invariato.

2.3 File Excel di esempio

I modelli di importazione attuali si trovano in Resources/ExampleFiles: ProgTrack_example_blood_progesterone_import.xlsx, ProgTrack_example_urine_pdg_import.xlsx, ProgTrack_example_sperm_import.xlsx e ProgTrack_example_weight_import.xlsx. Contengono colonne separate Animal ID e Sample ID.

3. Panoramica dell'interfaccia utente

La finestra principale è organizzata come segue:

  • Barra dei menu – File, Strumenti, Impostazioni (Lingua, Convenzioni, Backend), Info (Informazioni sul programma).
  • Pannello sinistro – elenca animali disponibili e archiviati, offre filtri per fase del ciclo e azioni rapide (nuovo, modifica, importa, archivia, ripristina, elimina).
  • Area principale – contiene Grafici e le schede fornite dai plugin attivi, tra cui Report, Flow Track, Heritage Track, Gestione Gabbie, Medi Track e Project Track quando installati e consentiti.
  • Barra di stato – messaggi su importazioni, errori e passaggi di elaborazione. Quando il plugin Master Track è installato, la barra di stato mostra anche l'utente corrente e lo stato di accesso (o «Ospite» in modalità sola lettura). Fare clic sull'etichetta di stato per accedere a un menu rapido per login, logout o cambio password.

4. Gestione degli animali

4.1 Creazione delle schede

Usare l’azione del pannello laterale per creare una scheda. Nella categoria Tutti ProgTrack chiede prima il ruolo, poi apre l’editor corrispondente. I campi obbligatori dipendono dal ruolo; campi ID, progetto, origine, genotipo, genitori, alloggio e limiti appaiono quando rilevanti.

➕ Nuovo animale · Seleziona ruolo · Salva

Identità animale: ProgTrack identifica ogni animale tramite l'IPID immutabile Name | Species | DD.MM.YYYY | Origin. Dopo la creazione, nome, specie, data di nascita completa, origine e IPID non possono essere modificati da nessun account, incluso Lord. Gli elenchi usano il nome breve per leggibilità; relazioni backend ed esportazioni esatte conservano l'identità stabile.

4.2 Configurazione delle convenzioni Animal ID

L'IPID descritto sopra è la chiave d'identità interna di ProgTrack. Il distinto Animal ID pubblico può seguire una convenzione dell'istituto. Lord, Master o Manager lo configurano in Impostazioni → Convenzioni → Convenzioni di identità e ciclo di vita.

Comporre l'Animal ID con un massimo di cinque componenti ordinati. Ogni componente può essere inutilizzato oppure contenere Specie, Anno di nascita (AA), Anno di nascita (AAAA), Conteggio annuale, Conteggio assoluto, Sesso o Nome. ProgTrack unisce i componenti scelti con trattini bassi.

ComponenteValore generato
SpecieIniziali minuscole delle prime tre parole al massimo della specie registrata.
Anno di nascitaAnno a due o quattro cifre ricavato dalla data di nascita completa.
ConteggioSequenza univoca a quattro cifre, riavviata per anno di nascita oppure continuata tra tutti gli anni.
SessoM, F o U.
NomeNome dell'animale convertito in un elemento sicuro per l'ID.

Durante la creazione di un animale, il campo ID mostra un'anteprima mentre si inseriscono Nome, Specie, Data di nascita e Sesso. I componenti mancanti appaiono come XX o XXXX. Al salvataggio ProgTrack assegna la successiva sequenza libera. Le modifiche alla convenzione valgono per i nuovi record; un'identità di esempio definitiva errata viene eliminata e ricreata, non riscritta.

5.1 Tipi di misurazioni

MisurazioneUso attuale
Progesteroneng/ml; serie del progesterone ematico.
PdGµg/mg Cr; serie PdG urinaria.

5.2 Inserimento manuale

Usare gli editor specifici per ruolo per aggiungere, modificare o eliminare righe manualmente. Le schede disponibili dipendono dal ruolo selezionato e dai moduli installati.

5.3 Importazione da Excel

Le importazioni Excel si basano su nomi colonna esatti. Usare il pulsante di importazione corrispondente al tipo di dato e correggere date non valide, nomi vuoti o valori non numerici prima dell’importazione.

PulsanteColonne richieste
📈 Carica valori sangueAnimal ID, Name, Datum, Progesteron (ng/ml), F
📉 Carica valori urinaAnimal ID, Name, Datum, PdG (µg/mg Cr)
⚖️ Carica pesiAnimal ID, Name, Datum, Gewicht
🎈 Carica valori spermaAnimal ID, Datum, Name, % Motility, % Progressive, Sperms/ml

Dopo aver scelto un file valido, ProgTrack apre un'anteprima di sola lettura prima di scrivere animali o misurazioni. Conta l'intero file, mostra fino a 200 righe e classifica ogni riga come esistente, sconosciuta, archiviata, ambigua o non valida.

Controllare Animal ID, Nome, date, Sample ID e valori. Annulla lascia invariato il backend; Importa scrive solo le righe consentite per animali attivi esistenti.

Animal ID è determinante per l'abbinamento. Gli animali sconosciuti restano visibili come righe ignorate e l'avviso chiede di farli creare prima da un Manager. L'importazione di misurazioni non crea mai un animale e non apre una finestra d'identità.

Sample ID è una colonna separata e facoltativa per identificare il campione. Non sostituisce mai Animal ID.

5.4 PdG → Progesterone Converter

ProgTrack può stimare i valori di progesterone ematico a partire da misurazioni PdG urinarie usando una formula di conversione configurabile. Le stime risultanti vengono usate per la curva Prog. unificato e possono influenzare l'ombreggiatura delle fasi e le decisioni nei grafici.

Aprire il convertitore tramite Strumenti → Convertitore PdG→Progesterone. Selezionare prima un animale che disponga di misurazioni sia di progesterone ematico sia di PdG. La finestra mostra coppie di punti in cui i due valori sono disponibili per lo stesso giorno.

Flusso di lavoro:

  • Usare Auto Fit per calcolare la migliore formula di conversione da PdG a progesterone ematico per l'animale selezionato.
  • Regolare facoltativamente i coefficienti nei campi di input (ad es. per testare relazioni lineari vs. logaritmiche o per adattarsi a un riferimento noto).
  • Fare clic su Save / Apply per salvare la formula per quell'animale (o secondo la vostra configurazione locale, ad es. per ruolo o globalmente). La formula salvata viene usata per il ricalcolo futuro di Prog. unificato in grafici e report.
Raccomandazione: Adattate la formula su animali con un buon campionamento parallelo (più giorni con misurazioni sia di sangue che di PdG). Cambiare la formula modifica l'aspetto di Prog. unificato e può influenzare la classificazione delle fasi; documentate le modifiche importanti per il vostro team.

6. Grafici ed esplorazione dei dati

6.1 Modalità di grafico

Nella scheda Plots:

  • Selezionare uno o più animali nel pannello sinistro (fino a un massimo configurato).
  • Selezionare una modalità:
    • Combined – vista unificata di progesterone e PdG.
    • Blood (Pgr) – solo progesterone ematico.
    • Urine (PdG) – solo PdG urinario.
  • Usare le caselle di controllo per Progesterone, Weight ed Events per mostrare/nascondere le rispettive curve o marcatori.

Per leggibilità e prestazioni è previsto un numero massimo di animali che possono essere mostrati in un unico grafico (per impostazione predefinita fino a 5 animali). Se si seleziona un numero maggiore, gli animali extra vengono automaticamente deselezionati e vengono tracciati solo fino al massimo consentito.

6.2 Stili di linea, marcatori e colori

Utilizzare i gruppi Display / Line Style per regolare come vengono disegnate le serie di progesterone, peso e sperma.

Per una configurazione più globale, usare Impostazioni → Convenzioni (vedere la sezione 7).

6.3 Esportare i dati visualizzati

Usare File → Esporta report (.xlsx) per esportare dati per animali selezionati e un certo intervallo di date in Excel. Si possono poi eseguire ulteriori analisi o condividere il file.

Suggerimento: Usare l'esportazione Excel per preparare figure e riepiloghi per report: selezionate in ProgTrack esattamente gli animali e l'intervallo temporale di cui avete bisogno, quindi formattate e annotate il foglio esportato in Excel o nel vostro software statistico.

7. Lingua e aspetto

7.1 Selezione della lingua

Aprire Impostazioni → Lingua per cambiare la lingua dell'interfaccia utente. Le lingue disponibili sono elencate con il proprio nome (autonimo), indipendentemente dalla lingua attuale dell'interfaccia:

  • English
  • Deutsch
  • Русский
  • Italiano

Cambiare lingua ricostruisce menu, finestre di dialogo ed etichette usando il file messages_*.json corrispondente.

La selezione della lingua utilizza le bandiere SVG incluse in icons/ui/flag_*.svg.

7.2 Convenzioni e aspetto

Usare Impostazioni → Convenzioni per aprire la finestra delle impostazioni di stile. Qui è possibile configurare:

I controlli distribuiti in icons/ui usano esclusivamente SVG. Gli ID semantici in icons/ui/manifest.json selezionano grafica e tooltip localizzato; in questa cartella non esiste fallback PNG. I master modificabili sono in Q:\GitHub\Graphics\SVG\UI. I PNG nella radice di icons per splash, messaggi, lavori e tipi di file non rientrano in questa regola UI.

  • Colori principali per le curve di progesterone, peso, PdG e sperma.
  • Colori per iniezioni di FSH e marcatori di eventi (PGF, trasferimenti di embrioni, interventi, gravidanze, aborti, parti, misurazioni speciali).
  • Marcatori per ciascun tipo di misurazione (ad es. cerchio, triangolo).
  • Stili di linea.

Usare Reset to defaults se si vuole ripristinare lo schema di colori standard.

8. Salvataggio ed esportazione

8.1 Salvataggio del database

File → Salva database scrive lo stato corrente in una transazione del backend attivo. Per backup e trasferimento usare il flusso interchange completo, mantenendo insieme database e documenti gestiti.

8.2 Intestazione istituzionale dei PDF

Lord, Master e Manager aprono Impostazioni → Convenzioni → Identità dell'istituzione, inseriscono il nome e un logo PNG/JPEG facoltativo e attivano l'intestazione. Ogni pagina PDF supportata riceve a destra un'intestazione compatta; le immagini grandi vengono ridotte mantenendo le proporzioni.

8.3 Esportazione Excel

File → Esporta report (.xlsx) apre una finestra in cui è possibile:

  • Selezionare animali e intervallo di date.
  • Confermare l'esportazione di tutte le misurazioni e gli eventi rilevanti in una cartella di lavoro Excel.

Le esportazioni con dati animali includono sia il nome leggibile sia l'IPID (Internal ProgTrack ID). Usare l'IPID per collegamenti o re-importazioni esatte e il nome breve per il controllo umano.

8.4 Esportazione PDF (con plugin Animal Reports)

Se il plugin Animal Reports è installato, il menu File → Esporta report (.pdf) diventa disponibile. Usa il plugin Reports per generare un PDF per animale e mese. È possibile scegliere:

  • Cartella di destinazione.
  • Animali da esportare.
  • Anno e mese.
  • Lingua del report.

9.2 Lavorare tra più moduli

Usare la stessa identità animale controllata in tutti i moduli ProgTrack. La sequenza seguente mantiene coerenti schede ruolo, progetti, storia medica, report e alloggiamento:

  1. Configurare i ruoli animali: Lord, Master o Manager aprono Impostazioni → Convenzioni → Configurazione ruoli per scegliere schede attive, ordine, etichette/icone SVG, blocchi Nuovo/Modifica e visibilità di Nuovo animale per ruolo. Identità, alloggiamento, peso e genitori restano blocchi obbligatori.
  2. Assegnare l'ambito progetto: In Project Track associare utenti e animali, registrare assegnazioni IACUC/AWO, documenti, SOP e stato sperimentale, quindi scegliere Bozza, Attivo o Chiuso. La chiusura conserva associazioni e record.
  3. Mantenere la cronologia: Creare una volta l'identità animale immutabile, quindi usare l'editor per le modifiche consentite a genitori, alloggiamento e ciclo di vita. Gli eventi sperimentali e medici correlati restano disponibili in Medi Track e nei report animali.
  4. Ispezionare l'alloggiamento: In Gestione Gabbie selezionare Edificio, Unità, Stanza o Gabbia e aprire Ispezione. Un'ispezione di livello superiore comprende le strutture figlie occupate idonee. Fare clic su un'intestazione per ordinare e ancora per invertire.
Nota: Schede, animali o azioni mancanti indicano normalmente l'ambito progetto o i permessi dell'account corrente. Lord o Master possono controllare la colonna Effettivo in Gestisci utenti.

10. Risoluzione dei problemi e consigli

10.1 Plugin non disponibili

Se una voce di menu di un plugin è disabilitata o mostra un messaggio come "plugin is not installed", verificate che la cartella corrispondente esista sotto Plugins e contenga i file previsti. Controllare quindi il log tecnico per l'errore di import o inizializzazione e verificare che sia presente l'intero runtime pacchettizzato _internal.

10.2 Errori di importazione Excel

  • Colonne mancanti – usare i nomi colonna attesi dal codice: i file di progesterone ematico richiedono Name, Datum, Progesteron (ng/ml) e F; i file PdG richiedono Name, Datum e PdG (µg/mg Cr); i file peso richiedono Name, Datum e Gewicht; i file sperma richiedono Datum, Name, % Motility, % Progressive e Sperms/ml.
  • Librerie runtime mancanti – il launcher portatile dovrebbe già includere le librerie di importazione. Se una libreria manca in una release portatile, ricostruire o sostituire il bundle; solo chi usa la modalità sorgente deve installare pacchetti come openpyxl o pandas.
  • Righe non valide – le righe con date non valide, nomi vuoti o valori non numerici vengono ignorate; correggere il file Excel e importare di nuovo.

10.3 Prestazioni e sicurezza dei dati

  • Evitare di modificare file Excel molto grandi in una sola volta; se possibile, importate i dati a lotti.
  • Usare regolarmente File → Salva database.
  • Eseguire il backup congiunto del database e dei documenti gestiti tramite la procedura backend prevista.

10.4 Log tecnici

Gli account Lord e Master possono usare Master Track → Open tech logs per aprire la cartella dei log tecnici di supporto. Questa voce è separata dalla normale azione Logs, usata per i log di audit e delle modifiche agli animali.

La cartella dei log tecnici contiene file come progtrack.log, i log del launcher quando disponibili e log_locations.txt. Il file log_locations.txt elenca i percorsi rilevanti di applicazione, launcher, log di audit e cartella dell'applicazione per il supporto e la risoluzione dei problemi.
