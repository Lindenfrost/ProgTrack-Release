ProgTrack – User Guide

ProgTrack is an interactive application for tracking hormone levels, weights, surgeries and reproductive events in laboratory animals. It visualizes time series, enforces animal-specific limits, and provides planning and reporting tools through optional plugins.

1. Introduction & key concepts

ProgTrack is built around individual animals. For each animal you can record hormone measurements (blood progesterone, urine PdG), weights, sperm parameters, operations and reproductive events. Data are visualized as time-series plots and summarized in statistics.

Important concepts:

  • Animal – one record in the left sidebar. Each animal has a unique name and a specific role.
  • Role – determines how the animal is used (e.g. Egg Donor, Surrogate, Sperm Donor, Offspring, Partner, Breeding Animal) and which limits apply.
  • Measurements – time-stamped data for progesterone, PdG, weights and sperm quality.
  • Events – operations, embryo transfers, pregnancies, births, PGF/FSH injections and other reproductive events.
  • Plugins – optional modules for advanced planning, reporting, embryo tracking and team communication.
Current structure: ProgTrack is modular. The core program owns the animal database, plots, imports, language/style settings, and the main tab shell. Plugins add tabs, dialogs, permission gates, report tools, and workflow-specific data stores. Some modules are full tabs, some are separate windows, and some are feature gates which enable additional controls.

2. Starting ProgTrack & data files

2.1 Starting the program

  • Open Launcher.exe in the portable ProgTrack folder.
  • The launcher starts the first ProgTrack.v.*.py file it finds beside itself, in natural filename order. An explicit script can be passed with --script.
  • Keep Plugins, icons, lang, manual, and the active payload script beside Launcher.exe.
  • The compiled launcher already contains the required Python runtime; users of the portable bundle do not need to install Python packages.
Tip: If the application does not start, check launcher_error.log and launcher_fault.log under ProgTrackData/state/logs in a writable portable installation, or under the installed user-state root.

2.2 Backend profiles and managed data

ProgTrack uses one shared data-access layer with two deployment profiles:

ProfileUse
Standalone SQLiteOne local workstation or testing. The writable database must stay on local, non-synchronized storage.
Shared PostgreSQLNetwork and multi-workstation facilities. Users, animals, projects, plugin records, locks and configuration share the same backend.

Sign in as Lord and open Settings → Backend to select the profile used after the next clean restart. For Standalone SQLite, choose a safe .sqlite3 file name and an absolute local folder. Shared PostgreSQL exposes host, port, database, user, password, SSL mode, timeout, managed document storage and pool-size fields. Use Test connection before saving PostgreSQL. On Windows, the password is stored in Credential Manager; see the platform limitations below. Saving does not transfer data; use the complete export/import workflow. Deployment environment variables retain priority for headless administration.

The release provides Plugins/core/backend/certificates as the default folder for PostgreSQL CA bundles and, where required, client certificates and private keys. Local IT must configure this folder for the installation with institution-approved files and manage certificates and keys securely. The presence of the folder does not configure TLS automatically; select the files actually used by the deployment in the Backend dialog.

In a writable portable folder, mutable data lives below ProgTrackData: the default database is database/progtrack.sqlite3, configuration and preferences are under config, uploaded documents and the branding asset are under managed, logs and the Standalone lock are under state, and the default export folder is exports. Installed/read-only application folders use the Windows user-profile or Linux XDG roots instead.

The configured backend is the only operational data source. If it is unavailable, startup reports the error and does not switch profiles. The release contains the PostgreSQL client driver, but the server and its credentials must be provided separately; PostgreSQL and Linux deployment checks are separate installation tests.

IT: Provision the document share

IT creates a dedicated managed-document directory on the institution's SMB share (for example, share \\server-host\progtrack-managed with managed subdirectory documents). Permit SMB only on the institutional network or approved VPN; restrict TCP port 445 to approved client networks, apply the institution-approved SMB2/SMB3 security policy, and disable guest access and SMB1. Do not expose SMB directly to the Internet.

For the Shared deployment, install Samba on the same Ubuntu server that hosts PostgreSQL. Export one dedicated managed-storage root; all clients must reach that same server-side directory. The current example uses share progtrack-managed at /srv/progtrack-managed, with the two application-owned subdirectories documents and config-assets. The share is intentionally not browsable, so clients connect using its direct UNC/SMB path. Use a dedicated non-administrator OS/Samba account such as smb_app, add it to the share group, and never use the server-administration account for document access.

Example Samba share settings (adapt only the host interface, group, and path to the approved deployment):

[global]
server role = standalone server
netbios name = PROGTRACK
disable netbios = yes
smb ports = 445
server min protocol = SMB2_02
ntlm auth = ntlmv2-only
map to guest = Never
usershare allow guests = No

[progtrack-managed]
path = /srv/progtrack-managed
browseable = no
read only = no
guest ok = no
valid users = @progtrack
force group = progtrack
create mask = 0660
directory mask = 02770

Create the group and non-login service account only if they do not exist; ensure the account is in the group and is enabled in Samba's password database. Create the share root and both application subdirectories with group ownership and setgid/group-write permissions, for example root:progtrack and mode 2770. Do not grant world access. Configure the host firewall to allow TCP 445 only from approved client networks and PostgreSQL TCP 5432 only from approved database clients; preserve a verified SSH administration rule before enabling a firewall. Do not expose either service directly to the Internet. If the server has multiple interfaces, restrict Samba to its trusted LAN interface as well as applying firewall rules.

After changes, verify sudo testparm -s, systemctl is-active smbd, sudo ss -ltnp | grep -E ':(445|139)\b', sudo ufw status verbose, group membership, and ACLs for the share root and both subdirectories. For a modern Windows/Ubuntu/macOS deployment using direct SMB paths, only TCP 445 should be needed; no guest access or SMB1 is required.

  1. Create a dedicated SMB account or group for ProgTrack storage. Do not reuse a personal account or PostgreSQL account. Keep server and system administration rights separate.
  2. Grant only the rights needed inside the managed-document directory: traverse/list, read/download, create/write, replace/rename, and delete files and subdirectories created by ProgTrack. On a Windows file server, open Properties → Sharing → Advanced Sharing → Permissions; grant the dedicated group Change and Read, not Full Control. On Security, grant that group Modify only on the managed subtree. Effective access is the intersection of share and filesystem permissions. On Samba/Linux file servers, apply equivalent share-level write policy and filesystem ACLs only to this subtree; do not use world-writable permissions such as 0777.
  3. Give client IT the DNS name, share, subdirectory, approved SMB account, and designated test directory. All clients must reach the same logical share, though their local paths may differ. Record the file-server OS/version and ACL policy.

IT: Windows client

  1. On Windows 10/11, sign in to the ordinary account that runs ProgTrack; do not use an elevated administrator session. In File Explorer press Win+E, enter \\server-host\progtrack-managed in the address bar, and authenticate with the approved SMB account if prompted.
  2. If a persistent drive letter is required, select This PC → More → Map network drive, choose a letter, enter \\server-host\progtrack-managed, select Reconnect at sign-in, and select Finish. The mapping must belong to the same non-elevated logon session as ProgTrack. Recheck after sign-out and reboot.
  3. In ProgTrack open Settings → Backend → Shared PostgreSQL. Enter the actual UNC or mapped path in Managed document storage. Prefer UNC when using separate ProgTrack storage credentials.
  4. If the SMB account for a UNC path differs from the PostgreSQL runtime account, expand Storage credentials and enter Storage user and Storage password. Username and path are client-local; ProgTrack protects the password in Windows Credential Manager. Blank-field fallback to PostgreSQL credentials is independent per field. The application override is for UNC paths; it does not replace credentials for a mapped drive. Do not remove an existing connection to another account to work around a conflict; ask IT to resolve it.
  5. Test connection checks PostgreSQL but does not save the profile. Save, close ProgTrack completely, reopen it, and verify a managed document using the ordinary account.

Microsoft instructions: share and map a network folder; share and filesystem permissions; Credential Manager; mapped-drive logon-session scope.

IT: Ubuntu-family Linux client

This example and Phase 3 native acceptance target are Ubuntu x86_64. Record the exact Ubuntu release/version used; other distributions require their own validation. IT identifies the ordinary ProgTrack OS user and local group allowed to access the share. Replace sample numeric IDs with the actual IDs. CIFS mount options control client-side ownership display; the server ACL remains authoritative.

  1. Install the CIFS client and create a root-only credentials file: 
    sudo apt-get update
sudo apt-get install cifs-utils
sudo install -o root -g root -m 0600 /dev/null /etc/samba/credentials-progtrack
sudoedit /etc/samba/credentials-progtrack
    In the editor enter the approved values (add domain=... only if IT requires it), save, and close. Never put a real password in a command, shell history, world-readable file, or public mount entry.
  2. Create the actual mount point and obtain the ordinary user/group IDs: 
    sudo mkdir -p /mnt/progtrack
id -u "$USER"
id -g "$USER"
    If multiple local users need access, use the numeric GID of a dedicated local group containing only authorized accounts.
  3. As IT, add this template to /etc/fstab, replacing 1000 with the IDs just obtained: 
    //server-host/progtrack-managed /mnt/progtrack cifs credentials=/etc/samba/credentials-progtrack,uid=1000,gid=1000,file_mode=0660,dir_mode=0770,nosuid,nodev,_netdev,nofail 0 0
    Keep the share path and mount point consistent with the institution's deployment.
  4. Reload systemd's generated mount units and mount/check the share: 
    sudo systemctl daemon-reload
sudo mount /mnt/progtrack
findmnt --mountpoint /mnt/progtrack --output SOURCE,FSTYPE,TARGET
    Confirm the expected server source and filesystem type cifs. Repeat after reboot and network reconnection. Prefer a real CIFS mount over an autofs-only trigger at the same path: ProgTrack's mount-anchor guard must see the actual network mount, not only an automount directory.
  5. Set PROGTRACK_STORAGE_MOUNT_ANCHOR=/mnt/progtrack in the environment used to launch ProgTrack. This must be the real mount point, not the documents subdirectory. A one-time shell export is insufficient if users normally start the desktop launcher; IT must set it in that launch context. In Settings → Backend → Shared PostgreSQL → Managed document storage, enter /mnt/progtrack, the share root. Do not append documents or config-assets; ProgTrack appends those directories. The Storage credentials group only reminds Linux users to use the IT-mounted folder; the Windows application override does not apply here.

The mount-anchor check is conditional on the environment variable. Without it, an existing but unmounted local directory cannot reliably be distinguished from the share. Do not configure Shared storage there unless IT has set and verified the anchor. Ubuntu references: persistent CIFS mounts and protected credentials; Ubuntu 24.04 mount.cifs options and ownership behavior.

IT and operator verification

  1. Use only an IT-designated disposable directory and test database. From the same non-administrator OS account that launches ProgTrack, create, read, rename, and delete a disposable file. Confirm the host/share, account, both ACL layers, and mount/path after login, reboot, and network reconnection.
  2. Configure the client-local path in Settings → Backend → Shared PostgreSQL, save and restart, then use a supported ProgTrack document workflow to create and read a disposable managed document. Verify its bytes/checksum through the documented application workflow.
  3. In a disposable deployment, verify a complete database-plus-managed-files backup and restore into a separate empty target, then read the restored document. Never test restore over production data.
  4. With IT, test insufficient share rights and an unavailable share. ProgTrack must report the managed-storage failure and must not write to a local directory or demo data. Unrelated database work may continue. On Linux/macOS verify the actual mount and configured mount anchor before accepting the result.
  5. Record OS/distribution and version, server OS, user/group, share path, filesystem type, mount/drive behavior, permissions, and failures. Troubleshoot DNS/VPN and TCP 445 first, then credentials, both ACL layers, Windows logon-session conflicts, Linux mount/credentials-file permissions, or the macOS volume name/login item. Escalate to IT; do not loosen permissions broadly or disconnect unrelated shares.

Writing these instructions is not evidence that they passed. The institution must record real platform walkthroughs before production use.

Users, roles and permissions are authoritative in the selected database: PostgreSQL for Shared and SQLite for Standalone. Local legacy permission files are no Shared fallback or override. Protect the local SQLite database, client secrets, application and plugin code/static resources using Windows ACLs or Linux/macOS ownership and modes; only appropriately authorized OS accounts should write them. Plugin operational records belong to the backend. IT manages OS accounts and permissions; ProgTrack role checks remain separate. One active session per account is enforced; persistent changes to an existing account require a new login.

The Backend dialog supports authorized database creation/selection, archive, backup, restore and deletion with the applicable authorization and confirmation. Back up and verify before destructive operations. SQLite-to-PostgreSQL transfer uses a complete package, preflight and empty-target import. Schema incompatibility requires explicit authorized maintenance; do not silently migrate.

Do not place Standalone SQLite on a network drive or cloud-synchronized folder. Do not copy a live database and managed files separately; use the complete interchange/backup workflow.

Standalone SQLite accepts one writable ProgTrack process. A second instance is refused while its live owner holds state/runtime/standalone.lock; stale local-process locks are reclaimed safely. Reviewed writes in either profile use backend revisions and entity locks. Only a Lord-authorized operation may force-release an entity lock, and a reason is required and audited.

A new Standalone database offers the fictional demo package under Resources/Seed; accepting it is optional. Shared database setup does not automatically import demo data. Existing databases are not seeded by profile selection.

3. User interface overview

The main window is organized as follows:

  • Menu bar – File, Tools, Settings (Language, Conventions, Backend), Info (About the Program).
  • Left sidebar – lists available and archived animals, provides filters by cycle phase and quick actions (new, edit, import, archive, restore, delete).
  • Main area – contains Plots and the tabs supplied by enabled plugins, including Reports, Flow Track, Heritage Track, Cage Track, Medi Track, and Project Track where installed and permitted.
  • Status bar – messages about imports, errors and processing steps. When the Master Track plugin is installed, the status bar also shows the current user and login state (or “Guest” in read-only mode). Click the status label to access a quick menu for login, logout or password change.

4. Managing animals

4.1 Creating records

For Experimental animal and Experimental offspring, enter the required Birth Date; Death Date is optional and stays blank for a living animal. Address is a separate collapsible section, not part of the Health Status checkbox row. Expand it to choose housing; use form scrolling on a small screen. Save and reopen to verify the new record. Existing saved identity remains immutable and field permissions still apply.

Use the sidebar action to create a record. In the All category ProgTrack asks for the role first, then opens the matching editor. Required fields depend on the role; optional ID, project, origin, genotype, parent, housing, and limit fields are shown where relevant.

New Animal · Select Role · Save

Animal identity: ProgTrack identifies each animal by the immutable IPID Name | Species | DD.MM.YYYY | Origin. After creation, name, species, complete birth date, origin, and IPID cannot be changed by any account, including Lord. Lists use the short name for readability while backend relationships and exact exports retain stable identity.

4.2 Configuring Animal ID conventions

The IPID described above is ProgTrack's internal identity key. The separate public Animal ID can follow an institution-specific convention. Lord, Master or Manager users configure it under Settings → Conventions → Identity and lifecycle conventions.

Build the Animal ID from as many as five ordered components. Each component may be unused or contain Species, Birth year (YY), Birth year (YYYY), Count per year, Count absolute, Sex or Name. ProgTrack joins the selected components with underscores.

ComponentGenerated value
SpeciesLower-case initials from up to the first three words of the registered species.
Birth yearTwo- or four-digit year taken from the complete birth date.
CountA four-digit unique sequence, either restarted per birth year or continued across all years.
SexM, F or U.
NameThe animal name converted to an ID-safe token.

When creating an animal, the ID field previews the result while Name, Species, Birth Date and Sex are entered. Missing preview components appear as XX or XXXX. On Save, ProgTrack assigns the next unused sequence. Convention changes affect new records; an incorrect finalized example identity is deleted and recreated rather than rewritten.

5.4 PdG → Progesterone Converter

ProgTrack can estimate blood progesterone values from urine PdG measurements using a configurable conversion formula. The resulting estimates are used for the Unified Prog. curve and can influence phase shading and decisions in the plots.

Open the converter via Tools → PdG→Progesterone Converter. First select an animal that has both blood progesterone and PdG measurements. The dialog shows paired points where blood and PdG values are available for the same day.

Workflow:

  • Use Auto Fit to calculate a best-fit conversion formula from PdG to blood progesterone for the currently selected animal.
  • Optionally adjust the coefficients manually in the input fields (for example, to try linear vs. log-like relationships or to match a known reference).
  • Click Save / Apply to store the formula for that animal (or according to your local configuration, e.g. per role or globally). The stored formula is then used for future recalculation of Unified Prog. in plots and reports.
Recommendation: Fit the conversion formula on animals with good parallel sampling (several days with both blood and PdG values). Changing the formula will change the appearance of Unified Prog. and can affect phase classification; document major changes for your team.

6. Plots & data exploration

6.1 Plot modes

On the Plots tab:

  • Choose one or more animals in the sidebar (up to a configured maximum).
  • Select a mode:
    • Combined – unified view of progesterone and PdG.
    • Blood (Pgr) – blood progesterone only.
    • Urine (PdG) – urine PdG only.
  • Toggle separate checkboxes for Progesterone, Weight and Events to show/hide those curves or markers.

For readability and performance there is a maximum number of animals that can be shown in one plot at the same time (by default up to 5 animals). If you select more animals than allowed, extra selections are automatically deselected and only up to the maximum are plotted.

6.2 Line styles, markers and colors

Event-line labels keep their normal font size and vertical level. Coincident or nearby labels occupy measured slots to the right, in date order (saved order for the same date); the lines remain at their real event dates. Dense groups may extend beyond the right edge: drag empty plot background to the left to reveal the later labels, or zoom out with the mouse wheel. Labels are not shortened, wrapped, staggered or turned into tooltip targets.

Hovering a visible event symbol shows only an enlarged yellow highlight with the same marker shape (also for FSH and weight points), not event text. Click a custom event symbol for date - event name(x), or date - event name(x/y) with a real applicable maximum. Counts belong to the recorded role and membership period; coincident symbols list each event in saved order. Historical status and relevant period context appear separately, without borrowing the current quota. The recorded role remains stored for counting/history but is not displayed in the popup. Clicked text stays until the next click or until its source is hidden; zoom/resize keeps it within the canvas. Vertical event lines do not trigger tooltips; use their labels. Existing built-in date-only and measurement value/unit tooltips remain unchanged.

Display → Events controls event symbols, lines and labels in configured role categories and All, independently of Steroid Track. A role with configured events but no dated history has a visible, disabled checkbox; a role without event capability or saved dated events has none. Historical events remain controllable after a role block is removed. Toggling Events does not change weights or saved records.

Use the Display / Line Style groups to adjust how progesterone, weight and sperm series are drawn.

For a more global configuration, use Settings → Conventions (see section 7).

6.3 Exporting plotted data

Use File → Export Reports (.xlsx) to export data for selected animals and a given date range to Excel. You can then perform further analysis or share the file.

Tip: Use Excel export to prepare figures and summaries for reports: select exactly the animals and time window you need in ProgTrack, then format and annotate the exported sheet in Excel or your statistics software.

9.2 Working across modules

Use the same controlled animal identity throughout ProgTrack. The following sequence keeps role tabs, projects, medical records, reports and housing information consistent:

9.3 Flow Track statistics

Open Flow Track Settings (gear) to select one of six egg-donor, four sperm-donor or two surrogate metrics and Per Surgery / Per Donation / Per Transfer or Total. Totals use summed numerators and denominators, not averaged percentages. Entered production/fertilization remains independent of individually recorded embryos: arrested or unrecorded embryos must not reduce production. Usable means currently transferred or frozen; unassigned embryos are not usable. Each embryo ID counts once, and thawed transfers remain transfers even if freeze history is retained. Unconfirmed implantation counts as not implanted; all transferred embryos remain in the denominator. A known zero is 0; an absent/zero denominator is No data. IVM and in-vivo MII remain separate. Bars, hover, detail dialogs and XLSX use the same calculations; per-oocyte yield is a ratio (for example 0.50), not a percentage. XLSX is a calculated snapshot, not a formula editor. Contradictory counts, duplicate identities and unresolved donor/procedure links are displayed as data inconsistencies without rewriting entered counts. The fresh bundled seed has four transferred and two frozen embryos in Tiffany’s 10 October 2024 collection / Denethor’s 11 October donation, frozen on 18 October. Existing databases are not migrated or replaced.

Flow Track interaction: hover text sits immediately below its own visible node, label and lifebars with a fixed two-point gap, not at the pointer or beyond an invisible click halo. It is centered on its source and clamped horizontally only to the canvas. Overlap with other nodes, labels, bars or lines is allowed and never shifts, flips or hides it. Only insufficient canvas space below makes it appear above the same source. Long text wraps without smaller type or truncation. If neither side can fit the complete text in an exceptionally small canvas, enlarge the view or open the existing details rather than covering its source. Tooltips are passive; source gestures remain available. Right-click a surrogate or freezer to show/hide its embryos. Double-click opens its existing details; a single left click opens details on release without dragging, while left-drag moves the node. Wheel zoom remains. Hold and drag the left or middle button on empty canvas to pan in both directions; a movement of four display pixels starts panning. Node/embryo markers, labels and lifebars retain priority over left-background pan. Panning changes only the viewport, not animal/embryo positions or data. Releasing outside the axes, leaving the canvas, losing focus, resizing/redrawing or changing tabs/session cancels the current gesture; press again to start a new one. Tooltips clear on leaving the canvas, item interaction, redraw or tab/session change; hovering never saves data or positions.

10. Troubleshooting & tips

10.1 Plugins not available

If a plugin menu entry is disabled or displays a message such as "plugin is not installed", check that the corresponding subfolder exists under Plugins and contains the expected files. Then review the technical log for the import or initialization error and verify that the complete packaged _internal runtime is present.

10.2 Excel import errors

  • Missing columns – use the current column names expected by the code: blood progesterone files need Name, Datum, Progesteron (ng/ml), and F; PdG files need Name, Datum, and PdG (µg/mg Cr); weight files need Name, Datum, and Gewicht; sperm files need Datum, Name, % Motility, % Progressive, and Sperms/ml.
  • Missing runtime libraries – the portable launcher should already include the import libraries. If an import library is missing in a portable release, rebuild or replace the launcher bundle; only source-mode users need to install packages such as openpyxl or pandas.
  • Invalid rows – rows with invalid dates, empty names, or non-numeric values are skipped; clean the Excel file and import again.

10.3 Performance and data safety

  • Avoid editing very large Excel files at once; consider importing data in batches.
  • Use File → Save Database regularly.
  • Back up the database and managed documents together through the supported backend workflow.

Core events in medical history

After a successful animal Save, Medi Track automatically retains performed surgery (including oocyte retrieval), embryo transfer, pregnancy, birth, abortion and Hearing test events. New offspring receive their own dated birth record; a live departure/handover includes its reason and recipient. Existing project, experiment, severity, identity and death documentation remains. Planned Surgery Planner appointments are not performed procedures. Sperm donation, pregnancy verification, PGF, FSH, progesterone and generic Measurement markers, and raw blood/weight/urine/sperm results do not create automatic medical records. Project event usage counts are independent of this clinical selection.

Authorized configuration users open Settings → Conventions → Role setup → New blocks or Edit blocks → Custom / Edit preset → Experimental limitation blocks. Add a block or edit its event definition and set Mirror in medical history, then save the event, preset and Conventions. The checkbox defaults off for both Counting and Limiting, independently of Line/Symbol or the preset's event-selection checkbox. It is shared by all roles using that definition, not a personal display preference. Cancelling Conventions discards the change.

The decision is captured when a new event is first saved, including backdated events. Enabling the checkbox does not backfill earlier events, even when edited; disabling it does not remove their existing records. Corrections and deletions retain the original and append linked, signed source annotations, also after detachment or retirement. Medi's table, PDF and XLSX show these separately from new procedures. Reading/reopening or restarting creates no extra record. Source permissions remain required; automatic documentation grants no permission to add or edit manual medical entries. No historical/seed backfill or database migration is performed.

10.4 Technical logs

Animal-change audit: Cancelling an editor does not create a successful animal edit. Unchanged empty death/severity fields and a different enumeration order of identical identified events are not clinical changes. Actual additions, edits and deletions remain logged with complete values; weight entries currently include the old and new history, not only the added point. Loading and viewing do not persist defaults or period metadata. The first Save uses the same rule as later saves: only real changes and their required consequences are written. Unchanged measurements retain their stored values, metadata and database rows; a no-op Save does not rewrite other animals.

Lord and Master accounts can use Master Track → Open tech logs to open the folder that contains technical support logs. This is separate from the regular Logs action, which is used for audit and animal-change logs.

The technical log folder contains files such as progtrack.log, launcher logs when available, and log_locations.txt. The log_locations.txt file lists relevant application, launcher, audit-log, and application-folder paths for support and troubleshooting.
